## Project conventions

Internal web app: every route is protected; users sign in at `/login` and land on `/dashboard`.

### Stack
- Next.js 16 (App Router, `cacheComponents` on), React 19, Tailwind v4
- Better Auth (`lib/auth.ts`, client in `lib/authClient.ts`) with the `admin` plugin; public sign-up is **disabled**
- Drizzle ORM v1 (rc) on Supabase Postgres. Relations use `defineRelations` in `db/relations.ts` (not the old per-table `relations()`)
- shadcn/ui (style `radix-nova`, Radix primitives, so `asChild` is correct) in `components/ui`; add components with `npx shadcn@latest add <name>`
- Icons: Solar (`@solar-icons/react`), imported per style, e.g. `import { WalletIcon } from "@solar-icons/react/linear"`. Search is `MagnifierIcon`, not Magnifer. lucide is only used inside generated shadcn components.
- Tables: `@tanstack/react-table` **v9** (`useTable`, `tableFeatures`, `createColumnHelper`; not the v8 `useReactTable` API)
- Forms: react-hook-form + zod (`@hookform/resolvers`); schemas live in `lib/validations.ts`. Use `Controller` with shadcn `Field` / `FieldError`
- Installing form deps needed `--legacy-peer-deps` (optional `effect` peer conflict in `@hookform/resolvers`)

### Auth and route protection
- `proxy.ts` (Next 16 replacement for `middleware.ts`) does an **optimistic** cookie check only: no cookie redirects to `/login?callbackUrl=...`; a cookie on `/login` or `/` redirects to `/dashboard`. `/api/auth/*` is excluded from the matcher.
- Real validation happens on the server with `requireSession()` / `getSession()` from `lib/session.ts`. Call it in layouts/pages behind `<Suspense>` (required by Cache Components); never trust the proxy alone.
- New protected routes go under `app/dashboard/...` (the layout already enforces the session) or call `requireSession()` themselves. Public routes must be added to `PUBLIC_PATHS` in `proxy.ts`.
- Roles: `admin` and `user`. Default role is `user`. Only an admin creates users (`authClient.admin.createUser`) and sets the role.

### Database and seeding
- Schema: `db/schema/auth-schema.ts` (generated by Better Auth CLI; re-export from `db/schema/index.ts`). `drizzle.config.ts` uses `schemaFilter: ["public"]` so drizzle-kit ignores Supabase's `auth`/`extensions` schemas. If drizzle-kit asks "created or renamed?", always choose create.
- Scripts: `npm run db:generate | db:push | db:migrate | db:seed`
- `npm run db:seed` (`db/seed.ts`) is idempotent and creates the admin and the default user from `.env`:
  `SEED_ADMIN_NAME/EMAIL/PASSWORD`, `SEED_USER_NAME/EMAIL/PASSWORD`. Never hardcode credentials; read them from env.
- Env: `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`. `.env*` is git-ignored.

### Domain: ledger pages

See `architecture/project-overview.md` (requirements) and `architecture/plan.md` (plan, DB design, routes, workflow).
A **ledger page** collects entries (payment `in` / `out` per customer, with payment method and optional game) and expenses until it is closed. Profit = in − out − expenses. Money is stored as integer cents (`lib/money.ts`).

- Schema: `db/schema/records-schema.ts` (separate from the generated `auth-schema.ts`, which Better Auth may overwrite). Relations: `db/relations.ts`.
- Routes (all under `/dashboard`): `/` pages list; a ledger page has three sections with a shared layout (`pages/[id]/layout.tsx`): `/pages/[id]` overview (metrics, top customers, top games, by payment method, latest entries), `/pages/[id]/entries`, `/pages/[id]/expenses`. The sidebar shows these three under "This page" while inside a page, and on phones `components/bottom-nav.tsx` (fixed, `md:hidden`) shows the app menu, with a second bar for the page's three sections stacked above it while inside a page. Metrics cards live only on the overview; Entries and Expenses show just their list. Others: `/customers`, `/games`, `/payment-methods`, `/users` (admin only).
- There are **no notes** anywhere (removed on purpose). Do not add note fields back.
- An entry can cover **several games** (`entry_game` junction table). Games are required for payments `in`, not for `out`. Metrics split an entry's amount evenly across its games.
- Customers have an optional photo and Facebook profile link. Photos are resized in the browser (`components/forms/image-picker.tsx`) and uploaded by the `createCustomer` server action (FormData) to a **private** Supabase Storage bucket through its S3-compatible API (`lib/storage.ts`, `@aws-sdk/client-s3`, `forcePathStyle`). Env: `S3_ENDPOINT`, `S3_REGION`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`, `S3_BUCKET` (server only). `customer.image_url` stores the app URL `/api/avatars/customers/<uuid>.jpg`; `app/api/avatars/[...key]/route.ts` checks the session and streams the object with a long private cache. Never store or expose Supabase URLs for these. Without an image the UI shows the first two characters of the name (`components/customer-avatar.tsx`).
- `drizzle-kit` in this repo is non-interactive for renames and data loss: pass `--hints '<json>'` (see its error output). If a column being dropped has data, move the data first.
- Roles (enforced in server actions, never only in the UI): users can create pages/customers/games/methods, add entries and expenses on **open** pages, and close pages. Only admins reopen pages, **delete pages** (entries, expenses and game links go with them via DB `ON DELETE CASCADE`), delete entries/expenses, delete customers (refused while the customer has entries; their photo is removed from the bucket), rename/disable/delete games and payment methods, and create app users. Nobody can add to a closed page.
- Mutations are server actions in `app/actions/*.ts`. Each one: `requireUser()` / `requireAdmin()` from `lib/authz.ts`, zod parse (`lib/validations.ts`), write, `revalidatePath`, and returns `{ ok, error }` through `runAction`. Do not pass inline closures from server components to client components; use `action.bind(null, id)`.
- Reads live in `lib/data/queries.ts` (`server-only`), with server-side paging and search. List state is in the URL (`?q=&page=&size=` plus filters, namespaced with a prefix when a route has two lists, e.g. `e_`, `x_`).
- Lists use `components/data-table/data-table.tsx`: a server-driven TanStack table that renders **cards below `md`** and a table from `md` up. Every list passes `columns` (stable, module-level) and `renderCard`. Keep new lists mobile-first.
- Forms: dialogs in `components/forms/` built with react-hook-form + zod + shadcn `Field`, calling the server actions directly.
- Pages read `searchParams` / the session, so wrap the async part in `<Suspense>` (Cache Components).
- Seed also creates the default payment methods (Cash App, Chime, PayPal).
- Do not name a shell loop variable `path` in zsh (it overwrites `PATH`).
